## Decision

TailPocket (github.com/jt-wang/tailpocket v0.2.4, MIT) is the optional way to reach a Server from any network, alongside LAN, Tailscale Serve and public URLs. We use it only as a transport: Kinuvo authentication is unchanged, and a Device still pairs with a one-time pairing code and holds a Device token. TailPocket builds on Tailcat (pinned to v0.6.0 by TailPocket), which gives an account-free encrypted WireGuard tunnel over direct UDP or free DERP relays. The relays have no SLA.

**Pairing.** The Server's tunnel host opens a one-phone TailPocket pairing window per Kinuvo pairing code, with that code as the window's payload. The invite text (`kinuvo1:…`) is the QR or link content: `kinuvo://pair?tailcat=<invite>`, and the bare invite is accepted when pasted. The client pairs the tunnel, which returns a Link (the phone's private key and the host's secret address) and the payload. It stores the Link in secure credentials, then runs the normal Kinuvo pairing with the payload's code over a loopback forward and keeps the resulting Device token. One scan does both. Switching a saved Server to a plain URL keeps the same Device token.

**Binding and revocation.** The host records which phone key used each pairing code while it delivers the payload, before the phone can reply. When a Device pairs with that code, the Server stores the phone key on the Device. Revoking the Device revokes the phone, through the running tunnel (other phones stay connected) or, while the tunnel is off, by editing the saved state. A revoked phone can no longer reach the Server; its Device token is already invalid.

**Server host.** The shim accepts paired phones on TailPocket's host listener and proxies each to a dedicated ephemeral loopback listener, as before: it trusts no forwarded headers, rejects browser Origin requests and the browser session endpoints, and applies the existing Device authentication and rate limits. The host saves its private identity and paired phone keys to `<home>/tailcat/state.json` before changes take effect, so they survive restarts. The file uses mode 0600 on Unix and inherits the directory ACL on Windows. "Reset private address" creates a new identity and drops every paired phone; it needs the tunnel stopped, and a process lock prevents it while the identity is in use. Shutdown is bounded; if upstream close hangs, keep the lock until it finishes or the process exits.

**Native library.** The Go shim (`libs/tailcat/go`) exposes a versioned JSON C ABI (ABI 3) over TailPocket's host and mobile packages. Desktop and CLI Servers support macOS arm64 and x64, glibc-based Linux arm64 and x64, and Windows x64. Prebuilts also cover Android arm64-v8a and x86_64 and iOS devices and simulators. The portable CLI JAR bundles every desktop library. Platform packages include their matching library, and Tailcat is unavailable on platforms without a compatible library. `libs/tailcat/build.sh` builds the libraries, using Zig for Linux and Windows, and records `STAMP` from the build script, sources and toolchain inputs. `scripts/libs.sh publish tailcat` uploads the binaries to a GitHub prerelease and pins their URLs and checksums in `libs/tailcat/prebuilt.json`. CI verifies the stamp and fetches the pinned binaries without compiling Go.

**Bindings.** The Kotlin module `libs/tailcat` implements the SDK's `TailcatForwarder` and the Server's `TailcatServing` ports (ADR 0029): FFM on the JVM, JNI on Android and, on iOS, a Swift wrapper that hands the linked static library's entry point to the shared Kotlin code. Only app shells depend on it. Native calls run off the UI thread; concurrent clients of a saved Server share one forward while in use, and a dropped socket invalidates it so reconnect creates another.

**Client model.** `Server.Remote` keeps an explicit URL or Tailcat transport. For Tailcat, `url` is an opaque local `tailcat:<uuid>` key, never a network URL or the secret; the Link lives in the credential store (`<key>.link`) next to the Device token. Unpair retains the Link; forget deletes both. A saved Server has one transport.

**Sharing.** Embedded Servers expose independent sharing options. Desktop can toggle and reset the tunnel only when it owns the Server. Android persists independent LAN and tunnel choices and restores them with the foreground Server service. iOS persists the tunnel choice and hosts it only in the foreground, since iOS suspends the app and its tunnel in the background; it offers no LAN sharing. The network listener and Device authentication are common Kotlin, served by Ktor CIO on every platform; the iPhone's listener is the same remote-only loopback listener behind the tunnel.

## Addendum: linking Servers

A Server can also link another Server ([0016](0016-external-agent-execution.md)) through the tunnel, with one invite and no address. Share Agents opens a one-phone pairing window for an existing link code (`execution.exposure.invite`, tunnel on only); its payload is `TailcatPayload(link = <link code>)`, where Device pairing sends `code`. The invite works as `kinuvo://link?tailcat=<invite>` or bare. The linking Server pairs through its injected `TailcatForwarder` (`execution.remote.join`, named for itself), keeps the tunnel Link and link code privately in `RemoteSecrets`, and saves the connection under an opaque `tailcat:<uuid>` address; the wire `execution.remote.save` cannot set one. Connections open a shared forward to `ws://127.0.0.1:<port>/ws` and a dropped socket invalidates it.

The sharing Server binds the phone to the link code when the linked Server first connects through the tunnel with that code and the phone matches the invite's window, as for a Device. Revoking the link code, or making it again under the same ID, revokes that phone (online through the tunnel, otherwise by editing the saved state). A link code with a bound phone refuses new invites until it is made again. Pasting an invite into the wrong place fails with a message, since the payload says which kind it is. `ServerFeature.LinkInvite` says the tunnel is on and `LinkJoin` that this Server can join; iOS joins only where the library loads.
