---
title: "Workflow Tool and Model steps"
description: "Workflow steps that make one tool call or one model request without a Session, run under a Workflow-level Agent."
---

Status: Accepted

A Workflow step is an Agent turn, an Approval, a Review, a Tool call, a Model request or a Condition. A Tool step makes one call to any tool the Agent could call (Server, plugin and MCP tools, `run_code`, `show_ui`) with templated JSON arguments and no model. A Model step makes one model request with no tools; its text reply is the output. Neither creates a Session except that a Surface Tool creates one to display its result, so proven work can run as cheap deterministic steps.

Both run under the Workflow's `agentId`, the Agent it runs as, which is required when a Workflow has either kind and must be an existing Agent. A Tool call passes through the same gate as a run: the Agent's Tool scope, Deny and Trust rules, Approvals, redaction and limits. An unknown or refused tool fails the step with the refusal as its error. A Model request uses the Agent's provider and model unless the step names another; its only context is the step's `system` text, with nothing from the Agent's personal context, Memory or Skills. Its transcript is discarded, and it never appears in Session listings.

A Session exists only when a Tool call needs an Approval. The step creates one then, publishes the pending interaction there, answered through `session.respond` like any other, and returns to running once it is answered. Like an Approval step, it cannot create Trust rules. Approval steps also publish their Session under the Workflow's `agentId` when it is set.

Step outputs stay strings. `{{steps.<id>.output}}` inserts a step's output; `{{steps.<id>.output.<key or index>...}}` parses the output as JSON and resolves the path, inserting a string result as is and anything else as compact JSON. Output that is not JSON, or a path that is missing, fails the step naming the reference. References also read run inputs with `{{input}}` or `{{input.name.path}}`. Missing inputs and skipped outputs render as empty text (null for a whole-value argument). JSON wrapped in one Markdown code fence is accepted. References work in Condition sides, Review values, Agent turn prompts, Model `prompt` and `system`, and every string value inside Tool `args`. An `args` string that is exactly one reference becomes the referenced JSON value itself, so objects, arrays and numbers keep their type. Every reference must name an ancestor step.

A Review step stops the run, shows data as a form and continues with what the user submits. Its `value` is a template like the others and `text` is the question, shown as the form's title. When the rendered value is a JSON object with at most 30 keys, the form has one field per key, prefilled: short strings as text, long or multi-line strings as long text, numbers as numbers, booleans as yes/no, nested objects and arrays as long text holding pretty JSON. Any other value is one long-text field holding the rendered text. Like an Approval step it asks in a Session under the Workflow's `agentId` (else the first Agent turn's Agent, else the first Agent), through the same `ask_user` question card answered with `session.respond`, and waits with status `WaitingApproval`.

Submitted answers become the output: a JSON object with the input's keys and types (numbers and booleans converted back, nested fields parsed back from JSON, a field that no longer parses failing the step by name), or the plain text of the single field. Skipping the form fails the step with "Review declined" and the run with it. After a restart the step asks again in its same Session, as ADR 0042 describes for Approvals.

A run asks for the user in one Session: its Approval steps, Reviews and tools' Approvals share the first one any of them needs, titled with the Workflow's name. Each records what it asked and how it was answered as a tool call and result (`workflow_approval`, `workflow_review`, or the tool's own call), so the Session reads as the run's record and is never left empty and untitled. Saving a Workflow without changing its trigger or time zone keeps its next scheduled run.
