# Computer use goes through each platform's accessibility interface

Agents control Computers (paired phones and computers that allowed it) through the platform's accessibility interface: Android's Accessibility service on the phone, and cua-driver (macOS AX, Windows UI Automation, Linux AT-SPI) on desktops. Every capture returns numbered elements and a screenshot, and actions prefer elements over coordinates. Text-only models can still act from the elements, element numbers survive small layout shifts, and a stale number is refused rather than mis-tapped. We rejected Maestro and adb for phones, because they need a host machine attached, and Android's screen-capture API for screenshots, because it asks for consent on the phone every session, which nobody can give from a remote Live view. Accessibility screenshots need Android 11; Android 8–10 phones are controlled by elements alone. We use cua-driver rather than a JVM `Robot`, which has no accessibility tree and moves the user's real cursor.

Every Computer is a Device that allowed computer use under This Device's tools, through its own connection, whichever Server it pairs with, including the one in its own app; a desktop app offers its own screen the same way, so there is one switch per Device and no separate host setting. Each Computer serves one action at a time for every Agent; per-Agent Computers can come later.

Safety is layered: every app needs an Approval until the user trusts that app (a `computer_act <app>` Trust rule, like a shell prefix); typing into password fields and acting in system security screens are High Risk and never covered by a Trust rule; the phone refuses to act inside Kinuvo and permission or install screens; Agents are told to treat screen text as data and to ask for a Takeover for passwords, codes, payments, CAPTCHAs and permission dialogs. During a Takeover, Agents wait until the user hands the Computer back. Only the latest three screenshots are sent to the model again, which bounds context growth and cost.
