## Shipping path

JVM `HarnessServer` injects `AcpExecutionFactory` and an installation-owned durable `ExecutionRegistry` into `ServerRuntime`. Catalog is `execution-catalog.json`; external transcripts, phases and external Session IDs are `execution-sessions.json`, atomically replaced under the coordinator lock. Native Agent configuration and execution remain unchanged. No UI files, commits or pushes.

Normal `agents.list` includes external registrations. `agent.details` returns external identity metadata with `managed=true`. Normal Session create/send/stop/list/details/history/catch-up/unsubscribe routes dispatch by registration. External catch-up always resets the transcript window; updates currently send reconciled full windows. External transcript persistence is separate from native SessionLog, using the same public SessionChange entry representation. Native Runs are unchanged.

Prompt acceptance never ends a turn. ACP state notifications determine Running/RequiresAction/Idle. Process exit or update-flow failure sets Lost. Existing client disconnect does not cancel external execution or broker requests. Server restart preserves history and external Session IDs but restores every external Session as Lost: no automatic model-context resume. Create a new Session to continue. Resume capability is false.

## Public protocol for shared/app and shared/ui

All methods are typed `Api` members callable via generic `KinuvoClient.call`; events via `events`. Execution management, snapshots and answers currently require management authentication. No new client transport wrapper is needed.

- `ExecutionConnection.Acp(command: List<String>)`: executable followed by literal arguments, never shell split/eval. Inherits host environment/accounts. No runtime installation.
- `ExecutionConnection.Remote(serverId: String)`: reusable linked Server identity only. Remote adapter is now installed in common ServerRuntime; see remote increment below.
- `HarnessConnection(id, name, connection, host: String? = null)`. Host null means serving Server's `ConnectResult.serverName`; remote aliases may supply host.
- `AgentRegistration(id, name, connectionId, avatar?, cwd?, remoteAgentId?)`. ACP cwd required absolute; process starts there. Remote Agent ID required for Remote registrations. One command connection may serve multiple working folders. Save updates identity/cwd via `Api.RegisterExternalAgent`; native personal settings are not used.
- `ExecutionReadiness(configured, online, reason?, reasonCode?)`. `online` means negotiated, not an active turn. Codes currently checking/not_found/needs_sign_in/incompatible/unsupported/host_offline/unavailable. Authentication may be unknown when the harness does not offer auth/status.
- `AgentInfo` adds `executionKind` (Native/Acp/Remote), `connectionId?`, `host?`, `readiness`. Native defaults preserve existing behavior.
- `AgentDetails` adds `managed`, `cwd?`, `remoteAgentId?`. External settings placeholder must not be rendered/edited as native settings. Hide external Routines, Soul/Memory/Skills/MCP/Tools/risk policy. Approval policy belongs to the harness.
- `Api.ExecutionCatalog` → connections/status/capabilities + registrations.
- `Api.SaveHarnessConnection`, `DeleteHarnessConnection`, `RegisterExternalAgent`, `UnregisterExternalAgent`. Live connections and their registrations cannot be edited/deleted; referenced connections cannot be deleted. IDs cannot collide with an existing native Agent.
- `Api.ProbeHarnessConnection` (`execution.connection.check`, draft HarnessConnection) → `ExecutionProbe(readiness,title?,version?,authenticated?,authMethods?)`. Starts command and initializes v2, optionally queries auth/status, then closes. **Never creates a Session or opens a model turn.** authMethods is SDK wire JSON, read-only for now. No public authentication operation yet; sign in using the external harness.
- `Api.ExecutionCatalogChanged` (`execution.catalog.changed`) → ExecutionCatalog after CRUD/probe.
- `Api.ExecutionSnapshot` (`execution.snapshot`, ExecutionRef using local Session ID) → ExecutionSnapshot.
- `Api.ExecutionChanged` (`execution.changed`) → complete latest ExecutionSnapshot on every message/phase/request change; also available on reconnect via snapshot. Subscribe before fetching, reconcile by Session ID.
- `ExecutionSnapshot(sessionId,phase,messages,pending,stopReason?,externalSessionId?)`. `Lost` is distinct from Idle. Pending broker requests survive Device reconnect, not Server restart. Do not imply resumable context from saved history.
- `ExecutionMessage(id,role,text,payload?)`: keyed upserts; roles user/assistant/reasoning/tool. Complete ACP message content replaces accumulated chunks; omitted content preserves it. Tools preserve patch JSON in payload. Full transcript replacement allows authoritative upserts to replace streamed content without duplicate entries.
- `ExecutionRequest(id,kind,payload,options)`: kind Approval or Question. Approval `options` are typed `ExternalApprovalOption(id,label,kind)` with exact harness labels/kinds. Payload retains SDK request including subject/schema. Questions retain SDK form/URL/schema payload; do not treat all as existing native Questions.
- `Api.ExecutionAnswer` (`execution.answer`, ExecutionAnswer(sessionId,requestId,answer: JsonElement)) → Boolean. False means stale/already answered/lost. Invalid response fails before claiming request; duplicate responses cannot win twice.
- Approval answer JSON: `{"outcome":{"outcome":"selected","optionId":"<offered id>"}}` or `{"outcome":{"outcome":"cancelled"}}`. Option IDs validated against offered options.
- Question answer JSON: `{"action":"accept","content":{...}}`, `{"action":"decline"}` or `{"action":"cancel"}`. SDK typed decoding validates shape; full requestedSchema validation is not implemented.
- `session.capabilities` supplies external chat readiness and no attachments/tools. `Integration.Harness` advertises `acp` only on the JVM Server. Remote transport is installed in common ServerRuntime; no fallback.

## Explicit remaining work

Remote controls beyond send/cancel/answer remain followup. Native uses lifecycle dispatch delegates over existing Runs, SessionLog and brokers; native storage is not migrated to the external adapter interface. Advertised model/mode controls and mutations are not implemented; UI must hide absent controls rather than infer them. Login/auth elicitation outside Session negotiation needs a connection-owned broker before exposing sign-in actions. Probe returns auth methods but does not log in.

Tool patches are preserved and displayed as ToolCall entries; rich tool content/status rendering and terminal/plan/usage normalization remain incomplete. No automatic ACP resume/replay from a prior process is claimed. Current full-window subscription transport is correct for small transcripts but needs pagination/backpressure optimization. External push notifications/native Approval card projection are not implemented; render pending via execution snapshots/events. ACP filesystem paths are host paths; cwd existence is enforced by ProcessBuilder on create rather than registration save. Connection CRUD and Session startup share a Server mutex so a live connection cannot be edited between the guard and mutation.

SDK pinned published `com.agentclientprotocol:acp:0.33.0`; evaluated source `/tmp/kinuvo-acp-sdk-eval`, upstream commit `31de4eee7587a41cec5054750da159ac1727d4df`. SDK remains JVM-only; common interfaces carry neither SDK nor Koog types. StdioTransport Source/Sink constructor is deprecated upstream; replacement is still pending.

## Remote increment

New input-only `SaveRemoteLink(id,url,token)` is private Server storage, separate from the public catalog. JVM storage is `execution-links-private.json`; embedded hosts use the same private file plus durable catalog and external Session storage. `GrantExecution(ExposureGrant(id,agentIds))` mints a dedicated exposure credential; replacement and `RevokeExecution` revoke old access. A link credential can call only Presence and RemoteExecution, receives no broadcasts, and never authenticates as management. Grant allowlists exclude remote registrations (cycles are forbidden). Source Session ownership is persisted per grant token generation in private storage: only Sessions created through that grant can be read/sent/cancelled/answered; existing personal Sessions and other grants are denied even for the same exposed Agent. Self-link checks compare Server identity after authentication. Discovery is `DiscoverRemote(ExecutionRef(linkId))`; source selection remains `AgentRegistration.remoteAgentId` on `ExecutionConnection.Remote(linkId)`. Alias names remain local.

RemoteExecution currently uses source-authoritative snapshot polling (200ms), not pushed events. Snapshots preserve separate source Session ID and forward pending requests. Remote answers are validated/claimed at the source before local resolution. Native question answers use `QuestionsParams` JSON, native Approvals use the same offered-option outcome JSON as ACP; ACP requests retain their existing shapes. Source checks grant, exposed Agent and Session ownership for every operation. Native and external dispatch now implement the common SDK-free `ExecutionDispatch` contract (`NativeExecutionDispatch` and `ExecutionCoordinator`). Native Runs still use SessionLog; `executionSnapshot` projects its atomic persisted/live catch-up without moving the underlying storage. No SDK/Koog types enter remote transport.

## Execution API module separation

`harness/execution/api` is a small KMP module (`kinuvo.execution.api`) depending only on `shared/protocol`. It owns ExecutionFactory, ExecutionSession, ExecutionState, ExecutionBroker and ExecutionDispatch. No Server/core/Koog, SDK, Compose or process dependency enters this module. ACP production depends on api plus the ACP SDK; runtime is a test-only ACP dependency. Runtime depends on api and owns ExecutionCoordinator, registry/persistence, remote adapter/gateway and native snapshot projection. No compatibility aliases remain.

ExecutionDispatch now covers create, agent-owned snapshot, answer, send and stop. NativeExecutionDispatch delegates to the native SessionLog/Runs/brokers without exposing model history. ServerRuntime uses its dispatch selector for creation, source snapshots and remote answers; normal execution answers also support native pending requests. Native typed Approval/Question endpoints and storage remain intact. Existing native model providers remain under harness/core/provider dependencies; neither the API nor ACP imports them.

Remaining concrete scope: native list/history/catch-up retain their richer SessionLog protocol; the external adapter still uses full-window snapshots. This change does not move native model history or personal data, add external attachments/settings controls, or implement ACP resume.

## Resume, close, device access and account environment (2026-10-29)

New fixed API: `Api.ResumeExecution` (`execution.resume`, ExecutionRef → ExecutionSnapshot) and `Api.CloseExecution` (`execution.close`, ExecutionRef → Unit). Resume uses the SAME stored external Session ID via SDK v2 `Client.resumeSession`; v2 makes resume baseline when capabilities.session is negotiated, replacing v1 load. Missing capabilities.session rejects resume precisely and advertises resume=false. There is no context reconstruction or new-Session fallback. Remote/native resume is explicitly rejected. Resume errors retain Lost and the saved transcript. Explicit close cancels the turn, clears broker requests, releases the process and retains transcript/IDs; it works after registration removal. Execution generation identity guards prevent delayed cleanup from removing a replacement. Agent mutation guards now inspect only that Agent's live Sessions; connection edits still guard every live Session on the connection.

## Native ACP-facing entry point (2026-10-29)

`kinuvo acp --agent <existing-native-agent-id>` exposes exactly that native Agent using pinned SDK 0.33.0 `agent.v2.Agent`/`AgentSupport`. It connects through the normal CLI **running Server** path; absence of a running Server is an error, never a reason to open a second home. For a built checkout CLI, launch through `mise run exec -- <built-kinuvo-launcher> acp --agent <id>` to preserve checkout pins. Build-tool launch banners are not ACP data: generic clients should execute the built CLI launcher rather than `kotlin run`. Stdout is SDK stdio JSON-RPC; application diagnostics use stderr.

The ACP module owns SDK transport and lifecycle translation; CLI supplies the SDK-free ExecutionDispatch via KinuvoClient. No production dependency on Server runtime or Koog enters ACP. Only newly created connection-owned Sessions are registered with the SDK. Text prompts, authoritative keyed user/assistant/reasoning messages, tool status/input/output, Running/RequiresAction/Idle, Session cancellation, exact offered Approval options and native question forms are supported. Permission answers return through normal execution answers; form content converts back to native QuestionsParams lists. Cancellation is serialized with prompt start. Connection shutdown closes protocol and client scopes without stopping unrelated native Sessions. Client-supplied MCP servers/additional directories and non-text prompts are rejected. Resume/list/fork/configuration/management capabilities are not advertised or simulated. Native cwd remains Server-owned; session/new cwd does not relocate the selected native Agent.

## External streaming delivery (2026-10-29)

External transcripts now use atomic `SessionChange.Window` updates; the client replaces a complete window in one state publication rather than clearing it with Reset and adding rows separately. Coalescing notification workers retain the newest pending Session snapshot while delivery is blocked, suppress unchanged SessionInfo, and allow one external frame per client awaiting transport delivery. Pending Approval/Question and final snapshots remain authoritative. Prompt sends still record the message and return SendResult without waiting for ACP acceptance or completion; initial Session creation waits for startup. Acknowledgement timeout is extended while broker requests are pending; acceptance is not synthesized.

Sol review found writer failure could leave the delivery worker blocked, and a queued transcript Window could arrive after unsubscribe. Writer termination now disconnects in finally, cancelling external notification delivery. Windows capture a subscription generation; the writer discards invalidated generations and completes their delivery waiters. A new FrameDeliveryTest covers write failure with incoming still open. Added LatestNotificationsTest covers 2,000 history messages and 5,000 streamed updates with blocked delivery, pending and final states. ConnectedServerTest covers atomic windows and stable IDs.
